# 커플 에니어그램 심층 분석 — 랜딩 프로토타입

카카오톡 대화 내보내기(.txt/.zip) 하나로 관계 지표를 계산하는 **단일 HTML 프로토타입**입니다.
인스타그램 광고 유입 → 무료 맛보기(Teaser) → 12문항 2분 교차 검증 → 16쪽 리포트 베타 신청까지의 흐름을 실제로 눌러볼 수 있습니다.

## 섹션 구성 (위에서 아래로)

1. **Hero** — "100문항 테스트 풀지 마세요" + 카톡 파일 업로드 / 샘플 체험 CTA
2. **What is Enneagram** (`#what`) — MBTI는 '어떻게 행동하는가', 에니어그램은 '왜 그렇게 행동하는가'(핵심 두려움·핵심 욕구)라는 설명, 9유형과 날개(2w1·8w7) 표기 안내
3. **How it works** — 대화 내보내기 → 업로드 → 30초 맛보기 → 12문항 2분 → 유형 확정 (4단계)
4. **업로드 + 무료 맛보기 결과** — 두 사람 지표와 '본캐 티저'(양쪽 유형 카드)
5. **Accuracy** (`#accuracy`) — 카톡만으로 부족한 이유("괜찮아"가 2번·6번·9번 어느 쪽인지 구분 불가), 카톡 통계 → 12문항(두 사람 몫 6문항씩, 2분) → 유형 확정 3단계, 12문항 예시 3개
6. **16쪽 리포트** (`#report`) — 가상 샘플 커플(지민 여자 2w1 · 현우 남자 8w7)의 두 사람 프로필을 같은 분량으로 나란히 + '둘이 만나면', 6개 챕터, 가격 앵커링, 베타 신청
7. **Privacy / FAQ** — 로컬 분석 고지, 유형 정확도(2단계 교차 검증), 결제 전 단계 안내

12문항은 랜딩에서 아직 입력받지 않습니다(정식 오픈 시 리포트와 함께 수집). 랜딩은 베타 신청만 받습니다.

## 무엇이 동작하나

- **카톡 파서**: 모바일(iOS/Android) `2026년 11월 3일 오후 9:12, 지민 : …`, PC `--------------- 2026년 11월 3일 월요일 ---------------` + `[지민] [오후 9:12] …`, 24시간 표기 `2026. 11. 3. 21:12, 지민 : …` 세 형식과 여러 줄 메시지, 시스템 메시지(입장/퇴장/삭제) 처리.
- **.zip 해제**: 브라우저 내장 `DecompressionStream`(Safari 16.4+/Chrome 103+)으로 오프라인에서도 동작. 미지원 브라우저는 JSZip CDN 폴백.
- **무료 맛보기**: 메시지 수·기간, 대화 시작권(2시간 공백 기준), 평균/중간 답장 속도, 연타(5개+) 비율, 말버릇 TOP3(빈출/한 마디), 감정·애정·불안 키워드 밸런스(‰), 휴리스틱 에니어그램 유형 티저.
- **잠금 리포트**: 두 사람 프로필 미리보기, 6개 챕터 목차, 블러 미리보기, 19,900원 → 9,900원 앵커링, 베타 신청 모달.
- **개인정보**: 분석은 전부 브라우저 안에서 수행. 서버 전송·로그 저장 없음. 원문은 계산 후 메모리에서 폐기.

## 베타 신청은 어디로 들어오나

모달에서 신청하면 **Google Forms 응답으로 바로 접수**됩니다. 별도 서버·스프레드시트 없이
Google Drive 안의 설문지 응답 탭에서 확인할 수 있습니다.

- 설문지: `커플 에니어그램 베타 신청` (wjdduswo33@gmail.com 드라이브)
- 편집: https://docs.google.com/forms/d/1e8DKSjTMbIeUP4ZT3QTYFO4mZNJwtheu_4OgJtdLd40/edit
- 응답 보기: 설문지 편집 화면 → **응답** 탭 (또는 Google Sheets로 연결)
- 질문: 이메일(필수) / 인스타그램 ID / 신청 시각 / 유입 경로

`index.html` 의 `CONFIG` 에 접수처가 들어 있습니다.

```js
const CONFIG = {
  BETA_FORM_ACTION: "https://docs.google.com/forms/d/e/1FAIpQLSd.../formResponse",
  BETA_ENTRY: {
    email: "entry.1173838581", instagram: "entry.1139894040",
    at: "entry.1650453774", source: "entry.1725780174"
  }
};
```

설문지 질문을 새로 만들면 공개 응답 페이지 HTML의 `FB_PUBLIC_LOAD_DATA_` 에서
`entry.*` 값을 다시 확인해 `BETA_ENTRY` 를 맞춰야 합니다.
접수는 `mode:'no-cors'` POST 라서 브라우저는 성공 여부를 읽지 못합니다.
그래서 같은 신청을 방문자 브라우저 `localStorage('ce_beta_signups')` 에도 한 번 더 남깁니다(백업).

결제는 연결되어 있지 않습니다. 지금은 수요 확인용 신청만 받습니다.
